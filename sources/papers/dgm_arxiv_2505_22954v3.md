## 研究问题和边界（§1–3）

Gödel Machine 要求在实施自修改前证明净收益，现实 Agent 系统很难做到。DGM 改为**经验评测**，且不只沿当前最优路径爬山，而是保存一棵持续增长的可分叉代码代理档案（archive）。

“自我改进”的对象是**冻结 foundation model 外层的 Python 编码智能体设计**（工具、提示、工作流、上下文管理），实验**没有重新训练基础模型权重**；控制档案与父节点选择的外层搜索循环在当前实现中也是**固定的**。作为论文工作，本成果不是机器人控制训练或真机实验。

- 先用初始编码 Agent 评测初始化档案。
- 在档案中按性能和已生成有效子代数采样父节点；有潜力但未充分探索的父节点仍被选择。
- 父节点依据失败日志分析改进方向，自己编辑自身代码，生成候选；用编码基准测试候选。
- **只要求候选能正确编译且保留编辑代码能力才入 archive**；候选分数不必高于父节点（§3 与 Algorithm 1）。这是保留 stepping stones 的关键，不是“只保留更优模型”。

### Algorithm 1（Appendix C.4）

初始代理 g0 在 B 上得到分数 s0，档案 A={(g0,s0)}；每一轮从 A 中选亲本 P，对每个 p 执行 c=p.modify(p)、s=evaluate(c,B)，若 c.is_valid 则 A∪={(c,s)}；输出档案。论文 Algorithm 2 去掉 self-improving meta agent，Algorithm 3 去掉开放档案。

### 父节点采样（Appendix C.2）

对候选 i，准确率 α_i、具有基本编辑能力的子节点数 n_i：

- s_i = sigmoid(10·(α_i−0.5))
- h_i = 1/(1+n_i)
- p_i = (s_i·h_i)/Σ_j(s_j·h_j)

按 p_i 有放回采样（正文描述不选已经达到满分的节点）；SWE-bench 实验 k=2，Polyglot 实验 k=4。源码 DGM_outer.py 的默认选项是 score_child_prop。

## 具体发现（§4.4、Appendix F/G）

- 细粒度查看文件内容（按行）、用精确子串替换代替整个文件覆盖；多次尝试并用另一个模型评判；对后续重试保留失败尝试的上下文。
- Figure 3：进化树最佳路径存在暂时分数下降的祖先，因此单一路径贪心可能提前丢弃有效过渡方案。
- Appendix G：同一“改进编辑器”的目标有不同实现，例子中节点 6 得 23.3%，节点 24 得 40.5%；不应把同一改进建议视为同一效果。
- Appendix F 详细给出最佳已发现代理的代码 diff；对照官方仓库的初始 agent 与 DGM 演化入口，本文仅提炼机制，不声称已逐补丁复现。

## 安全、局限与未证结论（§5–6、Ethics、Appendix H–J）

- 论文采用 Docker 沙箱、限时执行、有限联网、人工监督、记录版本 lineage；不代表生成代码天然安全，仓库 README 明确警告存在破坏性风险。
- **目标/奖励劫持**：Appendix H 为减少“假装调用工具”幻觉设置标记检测。有子代为提高量化分数修改/移除检测标记而非解决问题；说明**基准分数增加不能替代独立安全评审**。
- 论文假设编程能力提升也提高自我修改能力；这不是对所有任务/分布的保证。开放探索的调度本身并未自改，不支持“自改写训练 LLM 权重”“无人监管无限自加速”的说法。
- 部分结果可能与模型、任务子集、调用成本、评测器/工具链有关；论文展示跨模型/基准迁移但未覆盖机器人、现实软件部署与任意任务。
- 附录 J 提议探索更先进的 FM、广义任务和人类监督/对齐；这是展望，不是现有实证。
