## 原文核对笔记

- **核心问题与复杂度分析（§1, Fig. 1）：** 机器人学习跨策略家族 $P$（IL / VLA / RL / WAM，数量 $N$）、仿真基准套件 $B$（LIBERO、RoboCasa、ManiSkill、RoboTwin、ALOHA 等，数量 $M$）与真实机器人构型 $R$（单臂、双臂、灵巧手、人形等，数量 $K$）高度碎片化。常规工作流每次交叉验证都需手写容器、观测适配与冒烟测试胶水代码，领域总集成代价为 $\Theta(N \cdot M \cdot K)$；通用编程智能体（Claude Code、OpenHands、SWE-agent）虽能临时打通单点配置，但缺乏机器人科研流程先验（procedural priors）与分层验证机制，难以实现可复用扩展。Nautilus 通过共享科研 Harness 将集成代价摊销至 $\Theta(N + M + K)$（其中策略-基准交叉接入由 $\Theta(N \cdot M)$ 降至 $\Theta(N + M)$）。
- **两层架构（§3, App. A–G）：**
  1. **基底层（Substrate，§3.2）：** 包含三个工程不变量——（a）**强类型接口契约（Algorithm 1/3/4）**：`Policy` 暴露 `reset()` 与 `infer(obs) -> Action`；`Benchmark/Env` 暴露 `reset(seed)` 与 `step(action)`；`Robot` 暴露 `reset()`、`get_observation()`、`apply_action(action)` 与 `safe_stop()`。（b）**分室隔离执行（Chambered Execution，App. E.1）：** 基于 Docker + `uv`（拒绝 conda/poetry/pipenv）将策略推理、仿真与真机驱动隔离在独立容器，依靠 `.classification` 标签与哨兵注释块实现幂等扩展。（c）**双层统一通信（§3.2, App. A.2）：** Tier 1 保留在机器人本地（ROS 2 DDS + 共享内存 IPC，1 kHz 驱动 / 50 Hz 状态聚合 / 15 Hz 应用环）；Tier 2 为面向智能体的唯一跨模块传输层——独立包 `policy_websocket`（`BasePolicy`、`WebsocketPolicyServer`、`WebsocketClientPolicy`、`ActionChunkBroker`），采用持久 WebSocket + msgpack NumPy 扩展（本机 RTT 约 $0.3\,\text{ms}$），提供 `GET /healthz`、`server_timing` 延迟统计与 `INTERNAL_ERROR` 异常透传。
  2. **内容层（Content Layer，§3.3, Table 6）：** 在基底之上以 **Guides + Sensors + State + Workspace Artefacts** 实现 L1–L6 六层栈（L1 为外部 Claude Code 循环）。L2 提供斜杠命令（`/nautilus:eval`、`/nautilus:train`、`/nautilus:benchmark`、`/nautilus:policy`、`/nautilus:robot`、`/nautilus:help`）；L3 调度子智能体（`env-generator`、`benchmark-generator`、`policy-generator`、`train-generator`、`model-finetune` 及仅定义接口桩的 `robot-generator`）；L4 运行六类运行时 Sensors（Pre-action filter、Render-time auditor、Interface verify、Spec-comparison gate、Tiered smoke ladder L1/L2/L3-IL/L3-RL、Cross-run verification）与只读 FastMCP **State 注册表**（索引层 + JSON-Schema 规范层 + 四级模糊匹配）；L5 存放领域参考协议；L6 在目标仓库记录追加式过程日志（`.nautilus/run-log/`）与交接回执（`install.md`、`history.md`、`benchmark.md`、`cross-eval-report.md`）。其中 `/nautilus:eval` 在启动容器前先通过 Spec-comparison gate 将 `(Policy, Benchmark)` 归类为 `native`、`compatible-zero-shot`（按固定 5 步规则生成适配器：key rename → chunk split → dim slice → dim pad → image preprocess）或 `incompatible-action`（阻断并提示重训）。
- **基准可信度验证（RQ1, §4.1, Table 2, App. I Table 10）：** 按“跨策略交叉证据”原则验证生成包装器的忠实度，涵盖 IL（Diffusion Policy、ACT）、VLA（$\pi_0$、$\pi_{0.5}$、OpenVLA、SmolVLA）与 WAM（cosmos-policy、Motus）在 LIBERO、ManiSkill、RoboTwin、ALOHA、RoboCasa 上的官方权重复现。多数偏差落在 $\pm 2\%$ 以内，最大单点偏差为 $\pi_0$ 在 RoboTwin 的 $-3.8\%$（42.6% vs. 46.4%），如 $\pi_{0.5}$ 在 LIBERO（97.0% vs. 96.8%）、cosmos-policy 在 LIBERO（98.4% vs. 98.5%）、Motus 在 RoboTwin（86.9% vs. 87.0%）均高度贴合；另在 JAX 版 Loco-Mujoco 上验证了 PPO、SAC 与 TD3（Table 10 与 Fig. 5）。
- **可扩展性与消融实验（RQ2, §4.2, Table 3, App. D.5 & J Table 11）：** 构建“外科手术式剔除单一基准（Surgical-pruning）”受控测试床（$\mathrm{OpenPI}^{\setminus \mathrm{LIBERO}}$、$\mathrm{OpenPI}^{\setminus \mathrm{ALOHA}}$、$\mathrm{OpenVLA}^{\setminus \mathrm{LIBERO}}$，每配置 10 次独立试验），在 Claude Opus 4.7 与 Claude Sonnet 4.6 上对比：
  - **成本持平且可复用：** Nautilus 包装成功率 100.0% / 100.0%，任务成功率 98.7% / 98.0%（高于 Vanilla agent 的 95.4% / 93.2%），在 Sonnet 4.6 上交互轮次（115.5 vs. 158.0）、Token（9.5M vs. 12.4M）与费用（$4.76 vs. $5.19）反而更低，且产出符合统一契约的可复用模块而非一次性胶水。
  - **契约模板与验证注册表缺一不可：** 去掉 Tier-2 WebSocket 模板（`w/o template`，Opus 于 $\mathrm{OpenVLA}^{\setminus \mathrm{LIBERO}}$）后，包装成功率骤降至 55.3%、任务成功率降至 55.1%，轮次飙升至 607.5、Token 增至 41.7M、费用高达 $74.94；去掉已验证注册表镜像（`w/o verified image`）则使 Opus 轮次由 152.4 增至 431.2、费用增至 $14.80（2.3 倍），任务成功率降至 87.6% / 79.2%。
- **真机部署与硬件平台（RQ3, §4.3, App. B, C, H）：** 证明同一份仿真验证通过的 `Policy` 包装器可在不修改策略代码的前提下直接迁移至真机——只需将后端容器替换为 `nautilus-collect` 驱动的硬件容器。论文验证了四类硬件平台（Franka Panda 单/双臂、UFactory xArm 7、Allegro Hand 16-DoF、Unitree H1），并在 Franka Panda 上完成 $\pi_{0.5}$ 抓取放置部署（项目页说明从仿真通过到首次真机 rollout 约 1.5 小时，主要耗时在 Docker 构建；并指出开源权重无法直接零样本完成实验室实机任务，需经 `nautilus-collect` 采集微调恢复），在 Unitree H1 上完成 RL 行走策略部署。
- **明确边界与局限（§5, App. E, I, K）：** 当前仅覆盖复现、评测、部署与初步微调工作流；跨仿真器统一仅停留在环境 API 层而非物理引擎层；`robot-generator` 尚为接口桩，新增硬件仍需人工参与 SDK/关节限位/安全增益配置；主插件实现绑定 Claude Code 平台生态，受上游工具链变动影响；微调对比消融与通信层微基准测试被延后至后续工作。
