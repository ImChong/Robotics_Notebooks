## 核心摘录

1. **定位（摘要、第 1 章）：** MR-Robotics LAB 原先只接 MATLAB 轨迹；本文加 ROS 2 YAML 入口，保留原 JSON 回放格式，回放不需要在线 ROS 连接。
2. **转换（3.3 至 3.5）：** 至少 2 个点，按名字映射 6 个臂关节（UR5e、KUKA joint_a1–a6、joint1–6），夹爪通道名 gripper / finger_joint / tool / tool0，取值 0 开 1 闭；输出 N = max(2, floor(30T+0.5)+1) 个样本，最后一帧落在端点 T；各点都带速度时用三次 Hermite（式 1），否则线性（式 2）加有限差分估速度。
3. **序列导出（3.2、3.5）：** 段间关节位置差超过 1e-4 rad 即拒绝；夹爪状态切换时插入 1/30 s 的保持点，且前一段末端任一关节速度超过 1e-6 rad/s 就拒绝。
4. **结果（4.1 至 4.4）：** 解析三次参考轨迹上，有速度时位置 RMSE 约 2.91e-5 度（稠密、稀疏、不规则相同）；无速度时稠密 9.20e-5 度，稀疏 0.8536 度（最大 2.4243），不规则 0.4293 度（表 3）。UR5e 样条对（表 4）：无速度时速度 RMSE 0.05249 度/秒、最大 1.0682，位置 RMSE 仅 7.06e-4 度。取样条夹爪序列 403 点转成 243 帧、约 8.067 s，开 / 闭 / 开顺序保留；0.51 s 的指令在 0.533333 s 才出现。31 个 JS 测试与 19 个 Python 测试通过（Python 测试用 ROS 消息桩）。
5. **Apple Vision Pro（3.7）：** 用 Unity PolySpatial / RealityKit；自定义 shader、文字渲染、skinned mesh 受限；Firebase SDK 不支持 visionOS，改用 REST；无场景包围盒与相机图像；交互改为注视加捏合。
6. **作者承认的局限（5.5）：** 没有有代表性的 MoveIt 规划集合、没有真机执行、没有头显计时测量、没有用户研究；UR5e 测试轨迹来自预设路点而非 MoveIt；Python 测试没有真实 ROS 环境；不使用加速度；转换文件只用于可视化，不等价于控制器执行。
