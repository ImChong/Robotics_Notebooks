## 核心论文摘录（MVP）

### 1) 问题与总贡献（Abstract / §1）

- **链接：** <https://arxiv.org/abs/2607.26055>
- **核心贡献：** 通才操作策略普遍采用 **大 backbone + 多步去噪 + action chunk**；chunk 开环执行导致 **reactivity 不足**，而整管线 latency 又禁止高频重规划。πR² 在 **diffusion forcing** 的逐位置噪声日程上贡献两点：(1) **条件拆分**——proprioception 每 tick 刷新（快通道），vision–language 异步更新（慢通道）；(2) **latency-adaptive flow schedule（staircase）**——把 in-flight 动作当 inpaint 条件，**每次调用只走一步去噪**即吐出与实测延迟匹配的动作。可对预训练策略微调：在 **xArm6 + XHand** 上对 **GR00T-N1.7** 闭环重规划约 **4×** 快于基座（A5000 上约 **25 Hz**，约每 **40 ms** 吃一次新鲜观测）；相对最强基线仿真成功率最高 **+23%**、真机最高 **+30%**。

### 2) 本体感反应式 Diffusion Forcing（§3.2）

- **链接：** <https://arxiv.org/html/2607.26055>
- **核心贡献：** 标准 flow 对整段 chunk 用同一噪声级，动作绑死在同一陈旧观测上；diffusion forcing 给每个时间位独立噪声级。πR² 进一步把 conditioning 拆为：
  - **Fast channel：** 关节/力矩/指尖力等 proprioception，**每个去噪步**可读最新值；
  - **Slow channel：** VLM / 图像–文本特征异步刷新；用 **learned delay embedding** 容忍视语言滞后。
  直觉：视觉–语言给粗空间与任务引导，新鲜本体感驱动接触期精细修正。

### 3) Latency-adaptive staircase（§3.3）

- **核心贡献：** 朴素 diffusion forcing 假设去噪瞬时（\(d=0\)）。实测推理延迟 \(d>0\) 且随模型/GPU/网络变化。staircase 日程三段：
  - **Clean front（长度 \(d\)）：** 已在飞的动作钳为 clean inpaint；
  - **Ramp：** clean→noise 斜坡，使**单步去噪**吐出 \(d\) 个干净动作；
  - **Noise tail（长度 \(d\)）：** 缓冲滑动时追加的新鲜噪声槽。
  是 Train-Time RTC 的 diffusion-forcing 推广：RTC 对非 in-flight 区用共享噪声级；staircase 的 ramp+tail 使一次调用即可 emit \(d\) 个 clean actions。

### 4) 实验：仿真延迟扫描与真机四任务（§4）

- **仿真：** execution-horizon 扫描 + VLA 级推理延迟；相对 Flow Synchronous / Naive Async / Train-Time RTC，πR² 在延迟增大时更稳，成功率最高约 **+23%**。
- **真机：** xArm6 + XHand，控制 **25 Hz**；微调 GR00T-N1.7；任务含 Catch Book、Insert Box、Tidy Up Book、Don't Spill。πR² 在成功率与子目标 progress 上全面领先；相对最强基线最高约 **+30%**。力觉轨迹显示对接触尖峰反应更及时。

### 5) 局限与开源核查（§5 / 步骤 2.5）

- **局限（项目页/论文）：** 高度反应式示范难采；本体感条件化强于视语言；局部重规划可能无法推翻早期去噪已锁定的子任务方向。
- **开源核查（2026-07-30）：** 项目页链到 GitHub；仓库含 `deployment/`（`run_policy.py`、RealSense ZMQ、xArm/XHand 驱动）与 `learning/Isaac-GR00T`（NVIDIA Isaac-GR00T fork，`pir2` 训练旗标）→ **已开源**（训练+部署入口齐全；权重依赖自备 GR00T-N1.7-3B 与自采 LeRobot 数据）。
