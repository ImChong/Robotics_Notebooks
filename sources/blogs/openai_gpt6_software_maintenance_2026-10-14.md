## 为什么值得保留

- 把 coding agent 的价值从「生成新功能」扩展到「维护已有系统」：死代码、遗留实验/开关、flaky tests 与 CI 成本。
- 强调证据链与操作边界：跨代码、PR 历史、配置平台、生产 profile / telemetry 核实，不因静态搜索未命中就删除；保留 kill switch 等运行保护，并将不确定或高收益项交由人工验证。
- 给出从小范围试点、review 反馈到扩大扫描面的渐进方法，也报告了模型/effort 的成本与发现数差异。

## 核心摘录

### 清理死代码与过期实验

- 早期做法是为静态分析、日志和数据库查询维护专用脚本；面对反射、动态引用、间接依赖和可用于事故缓解的冷路径，仍会有误报或漏报。
- GPT-6 Astra 在较宽泛的任务下综合检查以往 PR、Slack 讨论、项目跟踪信息和生产性能 profile，为每项删除给出理由。团队称跨仓库合并了 **1,400+ 个维护 PR**、删除 **80 万行以上代码**；案例包括服务镜像从 3.31 GB 降至 1.72 GB，以及删除约 400 个视觉快照变体。
- 过期实验可能仍被生产执行，不能只看源码或对象标签。文章的方法还核验配置清单、常量的间接引用、云端配置与运行遥测，保留作为 killswitch 的开关，并优先审查资源开销较大的候选。一个标记为 Permanent 的开关经人工复核后移除，文章估计使主要服务 CPU 降低 **0.42%**。

### 模型成本与发现能力

文章在同一任务提示下，对超过 **6,000 个文件 / 100 万行代码** 的若干子目录做过比较，作者审阅结果后报告：

| 模型 / effort | API 成本 | 发现数 | 单条发现成本 |
|---|---:|---:|---:|
| GPT-6 Astra Ultra | $109.06 | 142 | $0.77 |
| GPT-6.1 Sol Ultra | $15.12 | 131 | $0.12 |
| GPT-6.1 Sol Medium | $5.27 | 86 | $0.06 |

GPT-6.1 Sol Ultra 找到 Astra Ultra **92%** 的发现，成本约为 **14%**。差异案例显示，Sol 漏掉了被其他 feature flag 依赖的常量；团队会把错误模式反馈到提示词中，并在新模型发布后重新检查这些修正。以上是特定内部代码库、模型配置与任务的报告，不是通用基准。

### Flaky tests 与 CI

- 作者建议让 agent 从近期 CI 运行中找 flaky tests，仅修复证据明确的简单问题，并提出 PR。
- 用 CI 历史估算每日节省分钟数后，团队后续合并约 **30 个 CI 优化 PR**；报告中位 CI 完成时间从约 **10 分钟降至 4.5 分钟**，P90 从 **12.5 分钟降至 6 分钟**。
- 一个 resolver 测试套件增加缺失 mock 后，从 **592.6 秒降至 29.8 秒**，仍保留全部 63 项测试（报告约 95% 降幅）。

### 推荐工作方式

1. 从一个边界明确的维护问题开始，要求 agent 找出候选、说明证据并提交小型 draft PR。
2. 人工核验生产行为、配置状态、间接引用与运行保护；收益不确定或影响面大的候选先检查，不直接自动删除。
3. 按固定任务对比模型与 effort，记录接受的发现数、成本和漏检模式；按实际收益排序，避免维护产物比问题更复杂。
4. 先扩展到子目录，吸收 code review 意见后改进下一轮提示；验证可靠后再扩大到全仓。

## 对机器人软件栈的启发（归纳）

可将该流程用于清查仿真训练与真机部署仓库中的废弃实验配置、旧 checkpoint 路径、未使用的 launch 参数和不稳定测试。候选项应结合训练/部署引用、CI 与仿真回归、机队日志及安全机制核实；真机急停、降级路径、回滚入口等可能是有意保留的冷路径，不能因「当前未触发」就删除。这里是对文章方法的机器人领域映射，原文案例来自 OpenAI 软件服务。
