## 论文要解决的问题

机器人间交互（Robot-Robot Interaction, RRI）缺少同时包含第一视角、第三视角以及事件数据的大规模数据。论文构建 R2RI，让多种人形机器人成对做源自人类社交行为的交互，并同时提供外部视角与机器人自我视角的 RGB 与事件流。

## 数据集构建

- **全部为仿真合成：** pyrender 渲染；环境光照，部分场景极暗模拟夜间。事件数据由 ESIM + FILM 帧插值的 video-to-event 流程从 120 fps RGB 合成；未使用真实事件相机，未报告相机型号和分辨率。
- **机器人：** Boston Dynamics Atlas v5、Unitree G1、iCub、Aldebaran NAO，每段为一对机器人。
- **视角：** 一对固定外部（exocentric）RGB 双目相机，位置围绕两机器人中点动态设定；每个机器人头部各一个自我视角（egocentric）RGB 相机。逐帧导出相机外参、3D/2D 关节位置。
- **交互类别：** 20 类，取自 INTER-X，兼顾有无碰撞（如 Hug、Kick、Push、Chase、Rock-paper-scissors、Thumb up）。
- **标注：** 人体 SMPL-X 姿态转成 14 关节骨架，用 SLSQP 逆运动学重定向到各机器人 URDF；自动标注 2D 框、2D/3D 关节（含被遮挡）、相机参数、物理碰撞管理器给出的碰撞接触、交互类别。
- **规模：** 约 5,000 个序列、650 万帧（120 fps），片段 1.8–23.5 s（均值 5.8 s）；6 个背景场景（4 室内 2 室外）；光照 100% / 50% / 25% / 5%；发布固定 train/val/test 划分（划分大小原文未给）。

## 基准任务与结果（论文报告）

8 个任务：机器人检测、2D 姿态、3D 姿态、2D/3D 姿态预测、碰撞检测、动作识别、sim-to-real 迁移。训练使用单张 RTX 4090。

| 任务 / 设置 | 事件 | RGB |
|------|------|------|
| 检测 YOLO26l mAP50 / mAP50:95（外部视角） | 98.8 / 89.1 | 98.1 / 94.2 |
| 2D 姿态 YOLO26l-pose | 95.7 / 81.3 | 97.3 / 91.9 |
| 最低亮度检测 | 88.1 / 66.0 | 0.7 / 0.3 |
| 最低亮度姿态 | 86.7 / 66.5 | 1.9 / 0.5 |
| 留出机器人 NAO 检测 mAP50 | 91.6 | 93.8 |
| 留出机器人 Atlas 检测 mAP50 | 91.5 | 50.6 |
| 外→内视角跨域检测 mAP50 | 1.9 | 83.5 |
| 内→外视角跨域检测 mAP50 | 65.2 | 62.7 |
| 碰撞检测 ResNet-50 F1 / AUROC | 0.774 / 0.808 | 0.771 / 0.654 |
| 动作识别 ResNet-50 Top-1 / Macro-F1 | 25.0 / 20.7 | 5.0 / 7.0 |

- 碰撞检测：基于真值 3D 姿态的 Random Forest F1 为 0.949。
- 3D 姿态（RGB 训练，MPJPE / P-MPJPE mm）：MotionBERT 25.6 / 20.5，MotionAGFormer 29.4 / 23.2，PoseFormerV2 55.9 / 35.8；论文指出 3D 预测里恒速基线很有竞争力。
- Sim-to-real（DHRP 数据集，平均 AP50）：DINO 55.4（最佳），RT-DETR 44.8，Faster R-CNN 29.6，YOLO26l 20.1。

## 复现与解释边界

- 合成数据，存在 sim-to-real 差距；事件流为从 RGB 合成而非真实传感器。
- 交互依赖人到机器人重定向，仅 4 种人形、以成对交互为主，不含意图或任务成功等高层语义。
- 基线代码 “将在录用后发布”；GitHub 仓库当前仅 README 和 assets；数据在 Hugging Face（页面可访问）。
- 数据集许可原文未说明，GitHub README 也未写许可。
