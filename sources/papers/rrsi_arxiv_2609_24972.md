## 摘录 1：问题与主张（摘要 / 项目页）

- **问题：** agent 能力不仅取决于冻结的基础模型，也取决于其周围的 prompts、control flow、tools、memory 与 context management。反复在固定 evolve set 上优化 harness，会记住题目或 benchmark 结构；演化集上的增益可能不迁移到分布外任务。
- **主张：** 不必关闭 harness 的编辑空间，而应正则化搜索轨迹与候选选择，让改进更可能对应可复用机制。
- **提案侧：** 退火 edit budget，控制单个候选能捆绑的独立改动数；将完整修改历史提供给提案器，减少重试已证伪假设；停滞时转向尚未探索的组件。
- **选择侧：** critic 在计分前筛查 benchmark-specific leakage；候选须超过未修改基础 harness 的噪声调整门槛；额外推理 token 必须由测得的收益支付；剪掉近期不再带来正收益的组件。
- **验证：** 三类任务域覆盖 coding、agentic workspace 与 engineering design；固定策略模型，衡量演化集收益、held-out 迁移与每次试验 token 成本。

## 摘录 2：官方代码入口

- **安装与测试：** git clone https://github.com/google-research/rrsi.git；pip install -e ".[dev]"；python3 -m pytest tests。
- **运行入口：** python3 rrsi.py --domain <coding|workspace|eng> smoke|baseline|run|status；baseline 初始化评测与 frontier，run 执行可恢复的迭代搜索。
- **每轮：** 为两个候选建立独立 git worktree，分析当前 harness、生成与审查候选，在 evolve set 并行评测，经 selection rule 选优，再推进 evolve/<domain> 分支并记录历史。
- **部署要求：** benchmark runner 使用不同 Python/benchmark 环境；配置 Vertex AI 项目变量或兼容的 LiteLLM 模型标识。Coding runner 使用 Harbor 环境，workspace / engineering runner 需安装 [agentic] 依赖。
- **对 wiki 的映射：** [sources/repos/rrsi.md](../repos/rrsi.md) 与实体页「源码运行时序图」。

## 摘录 3：结果与解释边界（项目页 / 摘要）

- 项目页汇总称，RRSI 在演化基准上的平均增益为 **+4.0 points**，held-out 基准平均增益为 **+3.4 points**，每个评测的 policy token 相对无正则化进化约 **−36%**。
- 项目页称展示的 held-out benchmark 均有改善；论文摘要概括八个基准、三类任务域，并报告最高 **+14.1 points** 的演化集提升、最高 **+4.7 points** 的 OOD 提升。
- 这些结果支持「在本文评测设定下，搜索正则化改善迁移并控制 token 成本」；它们不是对任意底座、工具栈或开放任务的保证。
