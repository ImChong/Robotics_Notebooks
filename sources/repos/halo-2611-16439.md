## 发布与依赖边界

官方 README 明确 **source code only**：训练所需 LeRobot 数据集、预训练 π₀.₅ 参数（默认从 `gs://openpi-assets/checkpoints/pi05_base/params` 获取）及训练后的 checkpoint 均需另备；视频模块模型权重也需另行下载。源码并非完整硬件示教/部署复现包。

OpenPI 主环境官方提示 Ubuntu 22.04 + NVIDIA GPU；其上游显存预估为推理超过 8 GB、LoRA 微调约 22.5 GB、全量微调约 70 GB，**属于上游参考估计**，非 HALO 当前配置实测。独立视频处理环境使用 Python 3.12、CUDA/PyTorch，默认权重约 13.6 GB，仍需实机验证资源占用。

## 真实入口与模块链路

1. 视频去手：`data/scripts/run_server.sh` → `hand_process` 视频管线 → CaRE-Ego / SAM2.1 / ProPainter + DiffuEraser → 修复 MP4 与质量报告。此步骤**只改变视频**，不会生成 LeRobot 数据集，也不会写动作/状态标签。
2. 修改 `src/openpi/training/config.py` 中 `pi05_mobile_aloha_rtc` 的 `repo_id` 等配置；`LeRobotMobileAlohaDataConfig` 调用 `MobileAlohaInputs` / `MobileAlohaOutputs`，读取头/双腕图像、关节、底盘动作。
3. `scripts/compute_norm_stats.py` 通过 `training/data_loader.py` 的 `create_torch_dataset`、`MultiVLADataset` 和 transforms 计算共同归一化统计，写入 `assets/mobile_aloha_example/norm_stats.json`（示例配置）。
4. `scripts/train.py` → `create_data_loader` → JAX `Pi0` 训练；`models/pi0.py` 的 RTC 训练前缀使用 clean prefix/noisy suffix，前缀不计 flow-matching loss；checkpoint 由训练脚本写出。
5. 推理：`policies/policy.py:Policy.infer` 提供缓存的上一个动作 chunk 前缀，`models/pi0.py:sample_actions` 预测下一段，output transforms 转回机器人动作。RTC 对应 JAX π₀.₅ 路径，不能假设 PyTorch 版本同步支持。

## 数据/运行约束

- LeRobot 数据需至少满足 `observation.image.{head,left,right}`、`observation.states.{left,right}`、`action.{left,right,base}` 及 task 元数据，三相机映射到 `cam_high` / `cam_left_wrist` / `cam_right_wrist`。
- `MultiVLADataset` 拼接各数据集帧，**按实际帧数比例**采样而不是按数据集均匀配比；`use_episodes=N` 取每个数据集前 N 个 episode。
- 数据帧率不一致时，基于各自 FPS 的时间 offset 不自动统一控制频率，需自查。多数据集共同统计值要在最终数据配比确定后重算。
- 源码当前 checkpoint 保存并不保证完整优化器状态续训，README 明确提醒勿假设严格恢复。
- 代码的 `use_delta_joint_actions` 参数目前被接受但不改变动作转换；不要将其当作已生效的切换选项。
- 视频模块含 ProPainter 非商用授权限制，面向商业落地需逐项审查模型与依赖许可。
