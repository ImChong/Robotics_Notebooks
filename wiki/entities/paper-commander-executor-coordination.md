# Commander–Executor：多角色协作操作的规划与策略迁移

**一句话定义：** 该方法把长程协作操作拆成「Commander 规划共享物体轨迹与角色线索」和「Executor 用共享物理策略完成仿真人形角色交互」两层。

## 英文缩写速查

| 缩写 | 英文全称 | 简要说明 |
|------|----------|----------|
| PPO | Proximal Policy Optimization | 低层物理策略训练使用的强化学习算法 |
| AMP | Adversarial Motion Priors | 用于鼓励自然角色动作的对抗运动先验奖励 |
| FSM | Finite-State Machine | 调度接近、抓取、交接、搬运与释放阶段 |
| A* | A-star Search | 规划角色到达站位的可行路径 |
| LLM | Large Language Model | 结合指令和场景图做高层语义任务分解 |

## 为什么重要

多角色操作难点不只是「让每个角色会抓」：系统还要明确谁先抓、谁等待、何时交接，以及不同角色如何沿同一物体目标协调。该工作把角色分工和物体级共享计划放在高层，把接触丰富的执行留给低层策略，并通过单角色到多角色的训练迁移减少对成对协作演示的依赖。

## 核心信息

| 项 | 内容 |
|----|------|
| **机构** | 天津大学（Tianjin University） |
| **任务** | 仿真人形角色的协作搬运、接力交接和多角色操作 |
| **输入** | 场景网格、任务指令、物体配置和各角色局部状态 |
| **Commander 输出** | 子任务、物体轨迹、角色站位、接触位置及抓取/释放信号 |

| **训练路线** | 增强物体/接触/轨迹的单角色预训练，再做多角色协作微调 |
| **开源状态** | 论文称将发布代码；截至 2026-10-19，所列 GitHub 仓库未公开可访问，暂无可运行实现 |

## 方法栈与流程总览

Commander 先把物体、空间关系和任务目标表示为场景图，让 LLM 做语义层子任务分解；随后结合 A* / Hybrid A*、退火采样等方法为角色规划可执行站位、接触位置和物体轨迹。有限状态机把计划落实为接近、抓取、交接、搬运和释放阶段。

Executor 的策略输入包含角色本体状态、物体状态，以及站位、接触点、共享物体轨迹和抓放提示。先通过物体形状、质量、接触与轨迹增强训练基础操作能力，再在双角色任务上微调；所有角色使用同一策略，依靠各自局部状态和共同物体轨迹完成分工。

```mermaid
flowchart LR
  task["任务指令 + 场景"] --> semantic["场景图与语义分解"]
  semantic --> geometry["几何规划：站位 / 接触 / 物体轨迹"]
  geometry --> cues["角色线索 + 抓放时序"]
  cues --> solo["单角色 PPO 预训练"]
  solo --> coop["多角色协作微调"]
  coop --> result["仿真搬运 / 交接"]
```

## 实验与评测

论文在 Core4D 的物体形状与轨迹上评估双角色协作，并另生成 Bezier 物体轨迹测试泛化；物体质量随机在 10–25 kg。对照物理交互方法，报告如下：

| 测试轨迹 | 成功率 | 物体轨迹误差 | 接触准确率 |
|----------|-------:|--------------:|-----------:|
| Core4D | 80.26% | 最终距离误差 0.147 m；平均轨迹距离误差 0.122 m | 86.23% |
| Bezier | 86.50% | 最终距离误差 0.162 m；平均轨迹距离误差 0.088 m | 98.17% |

复杂场景实验将搬运任务分解到多个目标区，并展示接力交接和扩展到多角色协作。消融结果强调：单角色预训练与多角色微调都不可缺；只给最终目标位置、移除物体轨迹或去掉同步抓取信号，都会削弱协作成功率。论文展示扩展到最多五个角色，但不应将其等同于五台真实机器人协作。

## 结论

**主要贡献是把语义任务分解、几何可行性和共享低层策略接成可扩展的仿真协作管线；现有结果证明的是仿真人形角色交互，不是真机协作能力。**

1. **高层计划要描述过程。** 共享物体轨迹比只给最终放置点提供更强的跨角色时序协调信号。
2. **抓放时序应显式编码。** 同步接触信号能减少多人各自抓取导致的不稳定。
3. **训练采用渐进迁移。** 单角色预训练提供基本操作技能，多角色微调再学习角色间配合；单独使用其中一阶段不足以完成协作。
4. **高层语义与低层物理职责分离。** LLM 适合分解任务，但坐标与路径还需几何规划检查可行性。
5. **复现受代码状态限制。** 论文给出待发布仓库地址，入库时尚无可执行代码，数值结果暂不能独立复现。
6. **真实平台迁移仍待验证。** 简化手部接触和复杂环境交互限制了向灵巧操作、障碍环境与真机部署的外推。

## 与其他工作对比

| 路线 | Commander–Executor 的区别 |
|------|----------------------------|
| 单角色人–物交互策略 | 扩展为对象中心的多角色共享策略，并用高层角色线索同步分工 |
| 固定抓取模式的协作生成 | 通过对象形状条件的接触位置和角色站位，适配不同物体与合作模式 |
| 直接端到端训练多角色策略 | 先单角色预训练再协作微调，缓解某一角色过拟合、另一角色失败的问题 |

## 局限与风险

- **仅有仿真结果：** 论文没有展示真实人形机器人部署；“humanoid”在实验中指受物理控制的人形角色。
- **灵巧操作有限：** 简化的球形手模型难以处理棒球棒、梯子等细长物体和高技能动作。
- **环境接触建模不足：** 低层策略未充分处理楼梯、斜坡和可变形障碍等复杂交互。
- **代码待发布：** 作者承诺公开，但截至 2026-10-19 指定 GitHub 地址不可访问。
