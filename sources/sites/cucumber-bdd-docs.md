- **维护方：** Cucumber
- **核查日期：** 2026-10-13
- **一句话说明：** Cucumber 将 BDD 描述为跨业务与技术角色建立共同理解、以小步迭代获取反馈，并形成可自动检查系统行为的文档实践。

## 文档要点

- BDD 的协作目标是缩小业务人员与技术人员之间对“要解决什么问题”的理解差距。
- 具体例子帮助团队先澄清行为；这些例子可以成为自动化检验与随实现更新的行为文档。
- Gherkin / Given-When-Then 是常用表达工具，而不是 BDD 的定义本身；维护困难的脆弱 UI 场景会损害反馈价值。
- BDD 依赖产品、开发、测试共同澄清例子；若只是开发者独自编写 feature 文件，协作收益不会自动出现。
