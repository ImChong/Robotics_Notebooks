## 核心命题

Agent 产出越来越顺畅、明显错误越来越少，人的**验证注意力**不会自动随并发扩张。文章不反对委托 AI，而是强调将独立判断、反例检验与签署责任嵌入工作流。

## 三段式认知风险（作者的框架）

| 阶段 | 判断权是否仍在人 | 提醒信号 |
| --- | --- | --- |
| Cognitive offloading（认知卸载） | 是；委托劳动但对结果负责 | 人能解释关键原因、取舍与失败边界 |
| Deferral（判断推迟） | 变弱；agent 的输出未经检验就成为下轮输入 | 连续引用前一个 agent 的总结，逐层脱离源资料 |
| Cognitive surrender（认知投降） | 基本放弃；直接把答案视为自己的判断 | 只看绿勾、无法解释关键代码/决策 |

作者将此与 **comprehension debt（理解债）**联系：系统能运行并不保证团队仍能在变更或故障时按需重建局部心智模型。该联系是作者的工程解释，不代表在本文中量化验证过的效应。

## 可操作的核心方法

1. **请求前立假设。** 写下预期结果、问题边界和至少一个可能出错的条件；没方向时可让 agent 寻找盲点，但不把其建议自动当事实。
2. **选择委托风险。** 在错误代价低的选择上完全委托；涉及安全、他人利益、资金或产品发布时，由人明确决定和负责。
3. **先设可反证的验收。** 先定义完成与验证范围，再让 agent 执行 E2E、属性测试或真实交互验证；检查绿了后分别回答“证明了什么”“没有证明什么”。
4. **读证据与决定，而不只读摘要。** 先看实际命令/日志/trace/截图，再审 diff，要求 agent 列出默认值、隐含假设、被排除范围及需求冲突时的选择；可随机抽问自己是否理解。
5. **反方论证与独立抽样。** 开放问题找不同模型反驳，并回到原始文档/计算；agent 汇总大量素材时主动抽检。
6. **量力审查。** 作者称产出与人愿意署名接受的内容之间存在 *orchestration tax*；堆积时改善验证或降低并发，而非再开更多 agent。
7. **保留技能校准。** 作者建议每周做一次无 agent 的关键实践、每月盘点不再练习的能力；将无法接受的输出原因沉淀成测试、配置或 hook。

## 关键边界与实例

- **600 行 PR：** 测试通过也可能掩盖事务顺序或默认值变化；要审 agent 做了哪些隐含决策。这是作者举例，不是实验数据。
- **Intent debt（意图债）：** 模糊任务由模型自行补完后，产物表面完成，但人可能已失去“为什么这样做”的上下文；作者建议本人先写受众、非目标和完成定义。
- **按需重建理解：** 不要求记住庞大代码库的全部细节；须知道自己缺少哪一块，并有能力局部恢复。
- **检验的局限：** 与实现存在相同误解的测试也会通过；“有绿色检查”不能当作整体安全性证明。
- **证据级别：** 文章是一篇工程经验与判断方法论，所引心理学术语、组织观察和外部研究仅按作者转述；本归档没有重复其研究实验。

## 机器人与知识库迁移（本站整理，非原文实验）

对 ROS 2 控制、仿真策略与 Sim2Real PR，按「事前预期—回归证据—未知风险—人类签署」整理验收；静态 lint 通过只代表该规则被满足，不代表机器人真机安全。对知识库 ingest，检查原文、来源和健康度脚本的真实输出，不能用 agent 自述替代 CI 记录。
