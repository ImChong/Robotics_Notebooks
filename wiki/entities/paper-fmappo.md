# FMAPPO：工厂多机任务分配与导航

**FMAPPO**（[arXiv:2609.14567](https://arxiv.org/abs/2609.14567)）——2D LiDAR + 任务状态去中心化 MAPPO；仿真 +106% 交付；真机暴露频率/通信 sim-to-real 差。

## 核心原理（方法）

任务场景是工厂 **多机器人多机台看护（multi-machine tending）**：若干移动机器人要自己决定「去服务哪台机床」并安全导航过去。论文的立场是 **去中心化**——不设中央调度器，每台机从本地观测决策：

| 组件 | 内容 | 为什么这样设计 |
|------|------|----------------|
| **特征融合** | **2D LiDAR** 测量 + **任务相关状态** 在同一网络内融合 | 这是 FMAPPO 相对 MAPPO 的唯一结构增量：避障信息与任务分配信息共享表示，而不是分两个模块各判各的 |
| **算法骨干** | MAPPO（多智能体 PPO） | 沿用成熟骨干，把变量控制在「融不融合特征」这一轴上 |
| **决策形态** | 去中心化任务分配 + 导航 | 加机器人不必重构联合动作空间；代价是全局最优性没有保证 |
| **落地管线** | 高保真仿真 + **ROS2** → 移动操作平台真机 | 实验中 **机械臂关闭**，只验证移动与任务分配这一层 |
| **部署参数** | 显式考察 **指令更新频率** 敏感性 | 真机上控制频率受通信与算力限制，这一条决定策略是否真能部署 |

**读法：** 论文做的是 **工程可用性** 论证而非算法新颖性论证——所以「机械臂关闭」「频率敏感性」这两条限定条件，和成功率数字同样重要。

## 实验与评测

### 仿真对照（vs MAPPO / SMAPPO，论文报告 effect size 大）

| 指标 | vs MAPPO | vs SMAPPO | 读法 |
|------|----------|-----------|------|
| 零件 **交付** | **+106%** | **+21%** | 提升最大的一项；相对 SMAPPO 只 +21%，说明 SMAPPO 已捕到部分收益 |
| 零件 **收集** | **+48%** | **+11%** | 同上趋势，量级更小 |
| **机台利用率** | **+31 pp** | **+10 pp** | 百分点，不是百分比——这是工厂侧最关心的产出指标 |
| **碰撞** | **−18%** | **−15%** | 安全侧收益在两个基线上接近，说明主要来自 LiDAR 特征进网 |
| **安全分** | **+14 pp** | **+6 pp** | 与碰撞率配对读，避免单看一项 |

### 真机

- 去中心化策略可协调多机服务多机台，在 **真实感知与控制约束** 下保持安全运行。
- **机械臂关闭**：本文验证的是移动 + 任务分配层，不含实际取放。
- **指令更新频率** 被单列为敏感性变量——部署前必须在目标通信栈上重测。

**验收提醒：** 上述百分比全部来自 **仿真** 对照；真机侧 abstract 未给量化表，本页也不补。跨论文引用时注意 **pp（百分点）与 %（相对提升）不是一回事**，交付 +106% 与利用率 +31 pp 不可并列成同一列。

## 与其他工作对比

> 下表只做 **定位对照**：前两行是论文自带的同协议基线（同任务、同仿真环境，可比），其余是路线定位，**不共享评测协议**。

| 对照 | 差异读法 |
|------|----------|
| **MAPPO**（基线） | 不做 LiDAR 与任务状态的特征融合；FMAPPO 的全部结构增量就在这里，交付 **+106%** 即这一条的代价换来的 |
| **SMAPPO**（基线） | 更强的对照，已部分利用感知信息；FMAPPO 相对它只 **+21%** 交付、**+6 pp** 安全分——这才是「融合」本身的净收益，比 +106% 更该作为选型依据 |
| **中央调度 + 单机导航**（工厂默认做法） | 分配由中央求解器给、导航各跑各的；FMAPPO 把两件事合进一个去中心化策略。取舍是失去全局最优与可解释调度，换来扩展性与对局部扰动的反应 |
| [MARL](../methods/marl.md) / [CTDE vs 去中心化](../comparisons/ctde-vs-decentralized-marl.md) | 定位入口：本文属 **CTDE 训练、去中心化执行** 一支；读该对比页可看清「执行期不通信」在本任务里意味着什么 |
| [PPO](../methods/ppo.md) | **骨干而非竞品**：FMAPPO 的改动在观测融合，不在优化算法；换 PPO 变体不改变本文主张 |
| [Sim2Real](../concepts/sim2real.md) | 本文的 sim-to-real 走的是 **高保真仿真 + ROS2 同栈** 路线，不做域随机化或真机微调叙事；**指令更新频率** 是它暴露出的具体 gap 项，可对照该页的路线分类读 |
