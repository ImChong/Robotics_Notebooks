## Part 1 · 用MDP描述问题

机器人控制中的每一步都包含三个对象：系统当前处于什么状态，可以施加什么动作，怎样的后果算作更好。强化学习用马尔可夫决策过程（MDP）描述这组关系，随后所有目标函数、价值估计和策略更新都建立在这套记号上。

### 1.1强化学习在求解什么

传统控制通常显式地写出动力学模型、约束、目标函数，然后在线做优化或反馈控制。强化学习换了一条路：

```
在环境里反复采样 (状态, 动作, 奖励)
通过最大化累计奖励，学出一个"状态 → 动作"的映射
部署时直接用这个映射做决策
```

这个映射就是**策略（policy）**。部署阶段，策略很像一个反应极快的反馈控制器：

*图1：强化学习训练通过奖励闭环更新策略；部署时则退化为低延迟的“观测→Actor→动作”映射。*

部署阶段无需在每一帧在线求解复杂优化问题，大量优化工作已经在**训练阶段**完成。强化学习可以概括为：**用采样和函数近似来求解最优控制**。

> **运控例子**：人形机器人的状态是几十维的关节角、关节速度、身体姿态和速度；动作是各关节的目标位置。强化学习要在仿真里反复试错，最终得到一个能实时跑在机器人上的神经网络控制器。它适合用RL，是因为动力学强非线性、有接触切换、目标多样（站、走、跑、抗扰），手写精确模型很难，而采样试错相对容易。

### 1.2 MDP：五元组

强化学习把"序贯决策"问题建模为**马尔可夫决策过程（Markov Decision Process, MDP）**，由五个要素组成：

| 符号 | 名称 | 含义 | 运控中的对应 |
| --- | --- | --- | --- |
|  | 状态空间 | 所有可能状态的集合 | 身体位姿、速度、关节状态、接触状态 |
|  | 动作空间 | 所有可能动作的集合 | 关节位置目标、力矩、残差动作 |
|  | 状态转移 | ，执行动作后状态如何变化 | 仿真器/物理世界的动力学 |
|  | 奖励函数 | ，对一步行为的即时打分 | 速度跟踪、站稳、能耗、姿态 |
|  | 折扣因子 | ，未来奖励的重要性 | 决定策略多看重长远 |

MDP的核心假设是**马尔可夫性**：下一状态只依赖当前状态和当前动作，与更早的历史无关。

这个假设之所以重要，是因为它让我们可以只盯着"当前状态"做决策，而不必把整段历史塞进策略——这是后面所有递推关系（Bellman方程）的前提。

### 1.3现实往往是POMDP

完美的马尔可夫性在现实中很少成立。真实机器人更接近**部分可观测MDP（POMDP）**：智能体看不到完整状态 ，只能拿到一个观测 。

原因很具体：身体的真实速度、地面摩擦、外部推力、负载变化通常无法直接测量；IMU和编码器有噪声；执行器有延迟、饱和、死区。于是实际训练里，策略的输入是观测而非完整状态：

当单帧观测不足以推断状态时，常见的补救是把**历史**喂进策略（历史观测、历史动作），让网络从时间序列里间接推断出那些看不见的量。这也解释了为什么运控策略常常加入历史动作、身体角速度、重力投影等输入——它们都是在用可观测量去逼近不可观测的真实状态。

*图2：POMDP中策略只能看见状态的投影，历史信息提供时间线索，帮助它间接推断隐藏量。*

> 训练阶段可以给critic提供仿真中的特权信息，例如真实速度、摩擦和外力；部署时的actor仍只接收真机可获得的观测。这种训练与部署的信息边界，构成了**asymmetric actor-critic**和**teacher-student**方法的基础。

### 1.4本部分小结

- 强化学习把问题建模成MDP ，核心是马尔可夫性。
- 目标是学一个策略 ，最大化长期累计奖励（下一章正式定义）。
- 现实多为POMDP，策略实际用的是观测  而非完整状态 ，历史信息可以弥补不可观测性。

有了MDP的记号，长期累计奖励可以写成明确的优化目标，策略梯度由此给出直接调整策略参数的方法。

## Part 2 · 策略梯度：直接优化策略

MDP给出了状态、动作、奖励、转移和折扣的表达方式。训练还需要一个可优化的目标：策略在随机轨迹上获得的长期回报。策略梯度（policy gradient）直接对这个目标关于策略参数求导，不要求先写出环境动力学的解析模型。

换成人话说：强化学习不是在找"某一步的正确动作"，而是在找一组更好的策略参数 。这组参数决定机器人在每个状态下更倾向于做哪些动作；动作会把机器人带到不同的运动轨迹；轨迹上的奖励加起来，就是这次尝试的总成绩。所以训练的本质就是不断调整 ，让策略更容易产生高分轨迹，更不容易产生低分轨迹。

### 2.3 horizon与rollout长度

理论上的目标对完整轨迹（可能很长甚至无限长）求期望。实际训练通常不等待一整个episode（一局）结束，而是让当前策略在环境里运行固定步数，再用这段数据更新策略。

这里要区分两个词：

- **horizon**：采样窗口的长度，也就是一次准备用当前策略往前跑多少步，常记作 。
- **rollout**：真的按当前策略跑出来的那段数据，里面包含observation、action、reward、done、value、log probability等记录。

所以更准确地说：

```
horizon决定rollout有多长；
rollout是按照这个horizon实际采集到的一段经验数据。
```

例如PPO里设置 `num_steps_per_env = 24`，意思就是每个并行环境用当前策略连续跑  步。这个  就是rollout horizon。假设同时有 `4096` 个并行环境，那么一次采样会得到：

```
4096 * 24 = 98304
```

条transition，这些transition合起来就是这一轮PPO更新用的rollout batch。

注意，**rollout horizon不等于episode length**。一个episode可能因为机器人摔倒提前结束，也可能最长能跑几百步、几千步；但PPO可以只截取其中固定的  步来更新。也就是说，episode是任务的一局，horizon是训练时人为规定的采样片段长度。

这是一个工程权衡。horizon太短，回报估计被人为截断、长期信用分配（credit assignment）做不好；horizon太长，单次采样耗时长、显存吃紧，而且数据更"陈旧"。on-policy方法（策略梯度属于此类）要求用**当前策略**采的数据来更新当前策略，所以通常的做法是：用当前  跑出固定horizon的一批rollout，更新一次（或几次）参数，然后丢弃这批数据、用新策略重新采集。截断带来的偏差，后面会用价值函数（bootstrap）来弥补——这是Part 3的事。

> **第2步的对数概率，在更新时用rollout数据重新计算，而不是直接使用采样时记录的数值。**
>
> 原因是：反向传播要的是  **关于当前  的计算图**（这样才能求出 ）。采样时顺手也能算一个对数概率，但那只是个用来记录/打日志的数值，是"死"的常数，不带梯度，没法拿来backprop。
>
> 不过在REINFORCE里，这个区分**不影响结果**：因为它是"采一批 → 只更新一次 → 丢弃"（第4步），在采样和这唯一一次更新之间  根本没变。所以"采样时算的log prob"和"更新时重算的log prob"**数值上完全相等**——存不存、算不算，都是同一个数。

这个区分要到Part 4的PPO才真正变得关键：PPO会对同一批数据反复更新K轮，过程中  一直在变，于是**必须**把采样那一刻的对数概率存成基准 `old_log_prob`（一个detached的常数），再和每轮重算的、带梯度的当前  相减取指数，得到重要性采样比 `ratio = exp(log_prob - old_log_prob)`。那时两者不再相等，这个区分就不能再含糊了。详见 4.3。

数学上的来源已经清楚了——log-derivative trick自然产出了 。但它的直觉意义同样重要： 衡量的是**策略对"它自己实际采过的那个动作"的认可程度**。值越大（越接近 ），说明策略本来就很确信要选这个动作;值越小（越负），说明这个动作在当时是个小概率的"尝试"。

梯度指向“让这个动作概率上升最快”的参数方向。将它乘上（更一般地，乘上advantage）：

- 当回报/advantage为**正**，就沿这个方向走，**增大**该动作概率;
- 当回报/advantage为**负**，就反方向走，**减小**该动作概率;
- 数值越大，调整的步子越大。

所以  本身负责"往哪调、调谁"，回报的正负和大小负责"调多少、是增是减"。两者相乘，恰好实现了"按效果好坏成比例地调整动作概率"。

### 2.7为什么不能用监督学习的loss？

到这里有人会问：既然策略是个网络、输出动作，为什么不能像监督学习那样，给定观测 ，让网络去拟合一个"正确动作" ，用

这样的均方误差（MSE）来训练？

答案是：**强化学习里没有“标准答案动作”。** 没有人预先规定“此刻髋关节应输出”。可获得的信息只有动作执行**之后**由环境给出的奖励。环境评价的是行为后果，并不提供逐步动作标签；这正是RL与监督学习的根本区别。

上面的MSE loss对应另一类方法——**行为克隆（behavior cloning）**。行为克隆属于模仿学习，需要一批专家示范作为标签；有可用专家轨迹时，它就是监督学习。强化学习面对的条件不同：没有专家，只有奖励信号，因此使用由回报加权的策略梯度loss，而非监督loss。

### 3.5 MC与TD：一条连续谱与bias-variance权衡

这是本部分的核心思想之一，也是很多人第一次接触时会卡住的地方。先把要处理的问题说清楚：训练critic或计算advantage都需要一个**学习目标**——一个“从  出发，未来到底能拿多少回报”的估计值 。真实的  不可直接获得（它是对无穷多条可能未来求期望的结果），手里只有采样出来的经验。问题变成：**用一条采样轨迹，如何构造尽量好的 ？**

"尽量好"有两个维度，先用大白话把它们定义清楚，后面反复要用：

- **偏差（bias）**：估计方法**系统性地偏离真值**的程度。把同一个状态的估计目标平均无数次，这个平均值和真实的  差多少，就是偏差。偏差大，意味着"平均而言你就估错了、估歪了"。

我们当然希望两者都小，但下面会看到，它们往往是此消彼长的。

**蒙特卡洛（Monte Carlo, MC）：只用真实奖励，绝不猜。** 最老实的做法是等这一整条轨迹跑完，把从  往后真实发生的奖励原样折扣累加，当作目标：

它完全不依赖任何"对未来的猜测"，每一项都是环境真金白银给出的奖励。所以它是 **无偏（unbiased）** 的——把无数条从  出发的轨迹的  平均起来，恰好收敛到 （这正是价值的定义）。代价是 **方差极大**： 把后续几百步里所有的随机性——每一步的动作采样、每一次环境扰动——全都塞进了一个数字里。

举个运控里的具体例子体会一下这个高方差：机器人在  时其实站得很稳、姿态很好，但它往后走了  步，中间第  步被随机扰动推了一把摔倒了，这一摔让整条轨迹的回报暴跌。于是这条轨迹给  记的账是"很差"。可要是换一条轨迹，它没被推倒、一路顺畅走到底，同一个  记的账又成了"很好"。**同一个状态、同样优秀的起点，只因为后面几百步的运气不同，target就天差地别**——这就是高方差的来源。

### 3.6 Actor-Critic结构

有了价值的概念，我们就能把Part 2的策略梯度真正落地成一个能训练的架构——**Actor-Critic**。它由两个部件组成：

- **Actor（演员）** ：策略网络，根据观测  输出动作（运控里通常是各关节目标力矩或位置的高斯分布 ）。它负责"做决策"。
- **Critic（评论家）** ：价值网络，估计当前策略下该状态的价值。它负责"打分"。

两者配合的逻辑是：actor采一批数据，critic根据这批数据估出每个时刻的价值，进而算出advantage ；actor再用这个advantage替代REINFORCE里的  去更新：

为什么这能降方差？因为advantage已经被critic减掉了状态基准 ，去掉了  里那块与动作无关的巨大波动，只保留"这个动作相对好坏"的净信号。critic越准，advantage的方差越小，actor的梯度估计就越稳。这是一种"分工"：actor不必从嘈杂的整条回报里硬学，而是听critic给出的、已经过滤过的相对评价。

一个常被忽视但很重要的点：**critic不是控制器**。它只在训练时用来算advantage、降方差，帮actor学得快、学得稳。一旦训练完成、要把策略部署到机器人上跑，通常 **只需要actor**——是  在实时输出动作， 可以丢掉。critic是训练期的脚手架，不是成品的一部分。

### 3.7 Value loss：critic怎么训练，以及一个重要误区

- **输入**  是观测 ；
- **网络输出** 是价值估计 ；
- **标签**  是价值目标 ——也就是3.5讲的那个"从  出发未来能拿多少回报"的估计。

这里唯一"不一样"的地方，也是关键：监督学习的标签  是人给的、固定的真值；而critic的标签  是我们**自己从采样数据里造出来的估计**。造这个标签，用的正是3.5那条谱—— 可以是MC return（无偏、方差大），可以是TD target （有偏、方差小），也可以是n-step或后面GAE对应的目标。选哪个，就是在选bias-variance的折中。（注意TD target里又用到了critic自己的输出 ，这就是3.4说的bootstrapping——用自己的估计造自己的学习目标。）

**value loss下降只表示critic的拟合误差变小，并不能代表策略回报上升。**

这件事初看反直觉——loss降了不是好事吗？问题在于要想清楚critic的loss到底在衡量什么。critic的唯一职责是：**尽可能准确地预测"当前这个策略"能拿到的回报。** value loss降低，只说明一件事——critic把当前策略的价值估得更准了。它**完全不关心当前策略本身是好是坏**。换句话说，critic是个尽职的"记分员"，你策略再烂，只要它稳定，记分员就能把这个烂分数记得准准的，loss照样漂亮地收敛。

举三个"value loss在降、策略却没变好"的典型情形：

- **reward设计有问题**：假设奖励函数错误地鼓励机器人原地不动来"避免摔倒"。那么"站着不动"就是一个高回报策略，critic会非常准确地预测出这套策略的回报，value loss完美收敛——可机器人永远学不会走路。critic尽职地估准了一个错误目标下的价值。
- **actor已经停滞**：哪怕策略卡住不再改进，只要它行为稳定，critic就能把它的价值拟合得越来越好，loss持续下降。loss在降，策略却一步没动。
- **数据质量差**：采样分布有偏、根本覆盖不到那些"好状态"，critic在这批坏数据上估得再准也没意义——它准，只是对这批坏数据准。

所以训练时**真正该盯的指标是回报曲线（episode return）和任务指标**（走了多远、摔了几次、速度跟踪误差多大），而value loss只是"critic拟合得好不好"的**辅助诊断**，不是训练进度条。把value loss当进度条看，是会被它骗的。

### 3.9 On-policy vs off-policy：一个埋给Part 4的雷

最后点一个性质，它会直接引出Part 4。先把两个词讲清楚，它们区分的是"用来学习的数据，是谁采的"：

- **on-policy（同策略）**：只能用**当前正在被更新的这个策略**自己采出来的数据来学习。策略一变，旧数据就作废。
- **off-policy（异策略）**：可以用**别的策略**（包括很久以前的自己）采的数据来学习，历史数据能反复利用。典型代表是Q-learning、DQN，它们把历史经验存进一个replay buffer（经验回放池）里反复采用。

**Actor-Critic（以及后面的PPO）属于on-policy。** 原因可以直接从3.6的策略梯度公式和GAE推导看出来：那些期望、advantage、value和梯度方向，默认都在**当前策略π\_θ的采样分布下**定义。换句话说，advantage是当前策略的advantage，value是当前策略的value，梯度方向也是相对当前策略计算出来的。这一切都依赖一个前提：**手里的数据，正是当前策略采出来的。**

**于是隐患出现了。** 想象这样一个流程，正是朴素Actor-Critic会遇到的尴尬：

```
1. 用当前策略 π_θ 辛辛苦苦采了一大批数据
2. 用这批数据算好advantage、算出梯度、更新一次 θ  →  策略变成了 π_θ'
3. 现在想接着用这批数据再更新一次……
   可这批数据是 π_θ 采的，不是 π_θ' 采的！
   对 π_θ' 来说，它已经是“别人采的数据”了，严格来说失效了。
```

这就是核心矛盾：**θ 一更新，策略就变了，之前那批数据就不再是"当前策略"采的了**，on-policy的前提被打破，理论上这批数据就该扔掉、拿新策略重新采。可是——机器人采样非常昂贵（要跑一大批仿真甚至真机），辛苦采一批只更新一次就扔，实在太奢侈了。

单次更新幅度过大时，新策略会远离采样时的旧策略。旧数据计算出的advantage和梯度方向随之失去代表性，更新可能沿着**错误的方向**推进；策略劣化后，后续采样质量也会下降。

于是一个尖锐的两难摆在面前：

> **一批on-policy数据来之不易，想多用几次榨干价值；但每多更新一步，策略就偏离采样时的策略一点，用得太狠数据就失效、甚至把训练搞崩。到底怎么在"多复用"和"别跑偏"之间取得平衡？**

这正是Part 4的主角 **PPO** 要回答的问题——它的信赖域思想、重要性采样、clip裁剪，本质上都是在解这一个矛盾。

### 本部分小结

- 评估"状态的预期未来回报"， 评估"状态-动作对"，二者之差就是 **advantage** ——衡量某动作相对该状态平均水平的好坏，正是策略梯度需要的低方差信号。
- **Bellman期望方程** 给出价值的递归结构；由它导出 **TD error**  与bootstrapping，是critic的训练基础。策略梯度路线用它"评估当前策略"，区别于value-based方法解Bellman最优方程。
- MC（无偏、高方差）与一步TD（有偏、低方差）是一条 **bias-variance连续谱** 的两端，n-step return居中；**GAE** 用参数 （配合 ）把整条谱统一成一根可调旋钮， 偏一步TD、 偏MC，常用 、。
- **Actor-Critic** 让actor用critic算出的advantage替代  来降方差；critic只是训练期脚手架（部署只留actor），且 **value loss下降 ≠ 策略变好**。Actor-Critic是on-policy的，更新过猛会让数据失效、训练崩溃——如何限制更新幅度，留给Part 4。

## Part 4 · PPO：让策略稳步改进

Part 3结尾留下了一个悬念：Actor-Critic是on-policy的，当前策略采来的数据只要策略一更新就会“过期”；而一旦某一步走得太猛，新策略的采样分布会和旧策略相差很大，训练可能崩盘。本节回答的问题是：**如何在改进策略的同时，约束新旧策略之间的差异。** 从信赖域思想出发，可以逐步推到PPO（Proximal Policy Optimization，近端策略优化）。它常用于人形机器人locomotion的训练，值得单独展开。

### 4.1问题动机：为什么"一步走太大"会崩

回忆Part 2的朴素策略梯度更新：

它告诉我们梯度的方向，但**没有告诉我们能走多远**。学习率  取小了，训练慢得让人崩溃；取大了，又会出大问题。问题的根源在于on-policy的本质：策略梯度的期望是在**当前策略π\_θ的采样分布下**定义的。

设想我们用旧策略  采了一批数据，算出梯度，然后一步把  推得很远。新策略  此时面对同样的状态，可能给出完全不同的动作分布——它会去到那些旧数据里几乎没出现过的状态-动作区域。可我们手上的advantage估计、value估计全都是基于旧分布的样本算出来的，对新分布根本不适用。于是这一步"改进"建立在错误的估计之上，很可能不是改进而是恶化。更糟的是,策略一旦劣化,接下来采到的数据质量也跟着下降,形成正反馈式的崩溃,**很难再恢复**。

在运控里这种崩溃极其直观:训练曲线本来稳步上升,某一刻reward突然断崖式下跌,episode length(机器人摔倒前能站住的步数)骤降,可视化里能看到机器人开始乱甩腿、原地抽搐、刚学会的步态瞬间瓦解。曲线崩了之后常常半天爬不回来。

所以核心诉求是:**每次更新都要改进策略,但要把新旧策略的差异限制在一个"可信"的范围内**——在这个范围内,基于旧数据的估计还大致靠谱。这就是"信赖域"(trust region)思想的出发点。

这个约束就是"信赖域":它在策略空间里画了一个以旧策略为中心的小球,要求每次更新都待在球里。在球内,替代目标对真实性能的近似才靠谱,重要性采样的方差才可控。

TRPO在理论上很漂亮,效果也好,但代价是要解一个**带约束的优化问题**:它需要用共轭梯度法求解搜索方向,再做线搜索(line search)保证KL约束满足,还要估计Fisher信息矩阵的向量积。这套实现复杂、计算昂贵,而且和现代深度学习里"多个epoch、minibatch、随机优化器"的工作流不太合拍。PPO想做的,就是**用一个简单得多的办法,达到差不多的效果**。

**情况一:(这是一个好动作,advantage为正)。** 我们希望增大它的概率,也就是希望把往上推(让)。目标里随增大而线性增长——看起来推得越多越好。但那一项把ratio卡在了:一旦超过,,这一项就变成常数,不再增长。此时在两项中取较小的那个,而对正的来说,被截断的常数项更小,于是选中它。**结论:当  还在  以内,目标正常奖励"提高好动作概率";一旦超过 ,目标变平、梯度归零,继续增大概率不再带来任何好处。** 直觉上就是:好动作值得鼓励,但别一口吃成胖子。

**情况二:(这是一个差动作,advantage为负)。** 我们希望减小它的概率,也就是把往下压(让)。因为,目标随减小而增大（变得没那么负）,所以最大化目标会驱使往下走。但把ratio卡在下界:一旦低于,被裁剪那一项变成常数。此时未裁剪的更大（更接近），裁剪后的常数项更小（更负），所以选中后者。于是**当  已经压到  以下时,目标不再继续给"压低差动作"发奖励**,梯度被掐断。直觉上:差动作值得抑制,但也别矫枉过正、一步把它的概率打到地板。

**把两种情况合起来看  的作用:** 当更新方向"合理"(在信赖域内, 离1不远),目标和未裁剪版本几乎一样,正常优化;当更新已经"过头"(ratio冲出  且方向是在加剧偏离), 让目标变成常数、梯度为零,**这一步对损失不再有贡献**。这样一来,优化器自然就没有动力把这个样本的ratio推得更远了。

这里必须强调一个常见误解:**PPO的clip不是硬约束KL,也不保证新旧策略一定接近。** 它没有像TRPO那样显式限制KL散度,理论上单步更新仍可能让某些样本的ratio超界(只是那些样本不再贡献梯度)。它做的事情更朴素:**让目标函数对"过大的更新"不再给奖励**,从而温和地、隐式地把策略变化拉住。可以把它理解成TRPO信赖域思想的一个**廉价的一阶近似**——丢掉了二阶信息和严格约束,换来了"只需一阶梯度下降、能跑多个epoch、实现极简"的巨大工程便利。实践证明这笔交易非常划算。

训练时我们做的是梯度下降,所以实际**最小化的是**,记作策略损失 。

### 4.7 KL监控与自适应调节

虽然PPO不硬性约束KL,但KL散度仍是训练中最重要的健康指标,实践中几乎总要监控它。我们一般用一个易算的近似KL(approximate KL)来估计新旧策略每步的差异。它的作用是个"仪表盘":

- **KL太大**,说明这一轮更新过猛、策略变化太剧烈,正是4.1里崩溃的前兆;
- **KL几乎为零**,说明几乎没在更新,可能学习率太小或数据用尽了价值。

围绕KL,有几种常见的自适应处理手段:

- **early stop(提前停止)**:在对同一批数据做K个epoch的过程中,一旦某个epoch后近似KL超过设定阈值,就立刻停止本轮剩余epoch,丢弃数据重新采样,避免在旧数据上更新过度;
- **自适应学习率**:根据KL动态调lr——KL偏大就降lr,KL偏小就升lr,把每步策略变化稳定在目标范围内。这在运控训练框架(如legged\_gym / RSL-RL这类)里非常常见,是稳定训练的利器;
- **调小clip系数** 或直接降lr,也都是收紧更新幅度的办法。

另一个值得盯的指标是 **clip fraction(裁剪比例)**:它表示一个batch里有多大比例的样本的ratio触发了裁剪(即  跑出了 )。这个数能反映更新的激进程度:**clip fraction过高**,说明策略想变得太多、大量样本都被截断,更新太激进;**clip fraction过低**(接近0),说明策略几乎没动,更新太保守或数据没被充分利用。健康的训练通常把它维持在一个适中的小比例上。

### 4.8 PPO的完整更新流程

把前面所有零件拼起来,PPO一个完整的训练循环长这样:

```
1. 用当前策略 π_θ 在N个并行环境里rollout若干步
2. 每一步记录:obs, action, reward, done, value V(o), old_log_prob
3. 用critic估计每条轨迹末状态的value,做bootstrap(处理未结束的episode)
4. 沿轨迹反向计算return Ĝ_t和GAE advantage A_t
5. 对advantage做归一化(减均值除标准差),稳定梯度尺度
6. 把整批rollout数据打乱、切成若干minibatch
7. 对同一批数据重复K个epoch:
      对每个minibatch:
          ratio = exp(log_prob - old_log_prob)
          算L_CLIP(策略损失)、value loss、entropy
          合成总损失L = L_policy + c1·L_value - c2·H
          反向传播,更新actor和critic
      (可选)监控近似KL,超阈值则early stop
8. 丢弃这批旧rollout,回到第1步用更新后的策略重新采样
```

### 4.9为什么PPO适合连续控制与大规模并行仿真

最后简短说说PPO为什么在人形运控这类任务上几乎成了默认选择:

- **只需采样,不需可微动力学**:PPO通过采样估计梯度,完全不要求环境(物理仿真)可微。这对接触、碰撞遍地、动力学高度非光滑的locomotion来说至关重要;
- **天生适配大规模并行仿真**:PPO是on-policy,样本效率本就不算高,但GPU并行仿真(成千上万个机器人同时跑)能在单位时间内堆出**海量** on-policy样本,正好补上这块短板——用算力换样本效率,在现代GPU仿真器上这笔账非常划算;
- **对密集reward友好、实现稳健**:运控的reward通常是密集的(每步都有前进、姿态、能耗等信号),PPO在这种设置下表现稳定,超参也相对好调。

当然PPO不是万能的,弱点也要点明:它**对reward设计和超参数较敏感**(熵系数、clip、lr、GAE的  都需要调),而且**对稀疏奖励不友好**——如果回报信号很稀疏,密集采样也难捞到有用的学习信号,这时往往要靠reward shaping或其他手段补救。

到这里,PPO的算法原理就讲透了。但我们一直把"策略 "当成一个抽象的概率分布在用——ratio要算它、熵要算它、log\_prob要记它。**对连续动作(关节力矩、目标角度这种实数向量),策略到底怎么"输出一个概率分布"?**  又是怎么算出来的?这正是Part 5要展开的:用高斯策略(Gaussian policy)把网络输出变成动作分布,以及运控里动作空间该如何设计。

### 本部分小结

- **动机**:on-policy的朴素策略梯度/AC一步更新太大,会让采样分布剧变、旧数据失效、训练崩溃(运控里表现为reward断崖、机器人乱甩腿);核心诉求是"改进策略的同时限制新旧策略差异"。
- **信赖域与TRPO**:用替代目标  把新策略的期望写成旧数据上的期望(必须靠重要性采样reweight),并用KL约束把更新关在信赖域内;但TRPO解带约束优化,实现复杂、计算贵。
- **PPO的clip**:用  替代硬约束——好动作概率涨过头、差动作压过头时,目标变平、梯度归零,让"过大更新"无利可图。它不硬约束KL,是信赖域思想的廉价一阶近似。
- **完整目标**:,三项分别负责"稳步改进策略""估准价值""保持探索";辅以KL/clip fraction监控、early stop、自适应lr等手段稳住训练。
- **精髓与适用性**:PPO的灵魂是"采一批on-policy数据、有限度复用K个epoch再丢弃",正好化解Part 3的on-policy悬念;它只需采样、天然适配大规模GPU并行仿真、对密集reward稳健,因而成为运控训练的主流,代价是样本效率不高、对超参和稀疏奖励敏感。

## Part 5 · 连续控制中的策略与动作设计

机器人关节目标是实数，不能像离散动作那样列出有限类别的概率表。连续控制通常把策略写成动作上的概率密度，再把采样结果映射为可执行的关节命令。这里需要处理高斯策略的参数化、动作物理含义和归一化等工程问题。

### 5.3 mean与std的直觉

把高斯的两个参数对应到训练行为上，会非常好记：

- **均值**：当前观测下策略"最想执行"的动作。它是策略学到的确定性意图。
- **标准差**：探索的范围。 大，动作在  周围撒得开，探索强，但动作会抖、轨迹噪声大； 小，动作紧贴 ，平稳，但容易过早收敛到一个局部解，没充分试过别的可能就"定型"了。

训练和部署的用法因此不同：**训练时按分布采样**（），保留探索；**部署时通常直接用均值**，丢掉噪声，让动作平滑、可复现，减少机器人的抖动。这也是为什么同一个策略"训练时看起来毛躁、部署时却很稳"。

健康的训练里， 一般会随学习推进自然下降：早期不确定、广撒网，后期收敛、动作笃定。如果  迟迟不降或反而涨，往往说明reward信号没立起来或学习不稳。

### 5.4 log\_std的实现细节

直接让网络输出  有个麻烦：标准差必须为正，而网络输出可正可负。实践中改为学习 ，用的时候再取指数 ，天然保证正性。为避免  过大（动作发散）或过小（探索熄火），通常对  做 **clamp**，把它限制在一个合理区间内。

至于  是不是该随状态变化：

- **固定/全局std（state-independent）**： 是一组与观测无关的可学习参数，所有状态共用。简单稳健，运控里很常用。
- **状态相关std（state-dependent）**：由网络根据  输出，理论上能"在难的地方多探索、在稳的地方少抖"，但更难训、更容易不稳。

没有绝对优劣，多数大规模并行运控训练默认用全局std起步，够用且省心。

### 5.7探索

连续高维控制里探索特别难，人形尤其如此。原因有二：一是**随机动作几乎必摔**——几十个关节同时乱给目标，机器人立刻失衡倒地，根本走不到能拿到正反馈的状态；二是**有用信号很短**——摔倒前可能只有零点几秒的有效经验，正样本稀疏。

探索的来源主要有三处：

- **策略自身的std**：5.3说的 ，是探索的主力，按分布采样自然带来扰动。
- **熵奖励（entropy bonus）**：在损失里加一项鼓励策略别太快变确定（Part 4提过），延缓  过早塌缩。
- **好的初始化**：从一个不至于立刻摔的默认姿态、合理的action scale出发，让策略一开始就有机会采到"没摔"的经验。

关键认识是：**探索不等于乱动**。有效的探索是在"还能恢复"的范围内试探不同动作，而不是把动作幅度开到最大随机抖。后面Part 6的课程学习和初始状态设计，很大程度上就是在帮策略把探索约束在可学习的区域里。

- 连续动作用高斯策略：网络输出均值 ，配上标准差 ，动作由  采样得到；多维独立时log\_prob是各维高斯对数密度之和，正是Part 2/4里梯度与ratio的入口。
- 是想执行的动作， 是探索范围；训练采样、部署用均值。实现上学  保正性并做clamp，全局std是稳妥起点。
- 动作不一定是力矩，运控主流是关节位置目标，计算关系为`q_target = q_default + action_scale · a`；action scale决定动作量纲，过大过小都会拖累训练。
- 观测归一化和优势归一化是稳定训练的算法级关键；探索难在易摔与信号短，靠std、熵奖励和好初始化，但探索要在可恢复范围内。

## Part 6 · 泛化与迁移

单一仿真环境中的训练还不足以支持真机部署。策略即使在固定地面、固定参数和固定命令下表现良好，改变摩擦系数、加入观测噪声或切换到真机后也可能失效。泛化与迁移关注的正是这类变化下的策略表现，包括课程学习、随机化和特权训练等方法。

### 6.1 Reward设计原则

先记住一句话：**策略只会最大化奖励函数给出的标量，它并不理解设计意图。** 设计者可能希望机器人自然、稳健地行走，但策略看到的只是一个标量奖励函数。只要存在更省力的方式把这个标量刷高，策略就会选择它，哪怕行为看起来荒唐。这就是 **reward hacking（奖励作弊）**。几个有代表性的例子：

- 为前进速度给奖励 → 策略学会前扑、靠惯性滑行，而不是好好迈步，因为滑行也能拿到速度奖励。
- 为节省能耗给奖励 → 策略干脆站着不动甚至躺下，能耗最低，奖励却不低。
- 为某个姿态高度给奖励 → 策略找到一个奇怪的踮脚或锁膝姿势把指标顶满。

避免这些不是靠堆更多reward项，而是把握几条原则：

- **scale要可比**：各项reward的量级要在同一个数量级上，否则大项会吞掉小项，小项形同虚设。一个权重设错，整个行为就跑偏。
- **正奖励vs负惩罚的风格**：正奖励"引导去做某事"，负惩罚"压制别做某事"。过度依赖负惩罚容易让策略变得畏手畏脚（动得越少罚得越少，最终趋向不动）；通常以正向塑形为主、惩罚为辅。
- **termination reward的权衡**：摔倒就终止并给惩罚是常见做法，但尺度要拿捏。判定太严（稍微晃一下就判摔），策略学不到从扰动中恢复的能力；判定太松，策略会用各种奇怪的"不算摔"的姿态赖在场上刷分。

原则讲清楚比列十几项reward term更重要——term是手段，可比的尺度和清晰的意图才是关键。

### 6.2课程学习（curriculum learning）

复杂任务从零开始学几乎一定失败：让一个随机初始化的策略直接学"在崎岖地形上小跑并听从速度命令"，它在拿到任何有用信号前就摔了一万次，正样本稀疏到学不动。

课程学习的思路是**由易到难**：先把任务调到策略当前能够得着的难度，等它学会了再加码。本质上，课程就是**逐步改变任务分布**——可以是初始状态（先从站稳开始，再引入扰动）、命令范围（先慢速直行，再放开转向和高速）、环境难度（先平地，再缓坡再台阶）、甚至reward权重（先重点学不摔，再逐步加大步态质量的权重）。这样始终把任务保持在"够得着但有挑战"的可学习区间内。

**自动课程**更进一步：根据策略当前的成功率自动调难度——成功率高就加难，低就退一档，省去人工逐级调参。

### 6.3域随机化（domain randomization）

仿真和真机之间总有差距（sim2real gap）：仿真里的质量、摩擦、电机模型不可能和真机完全一致。如果策略只在一组固定参数下训练，它会过拟合到这组参数，换到真机就失灵。

域随机化在训练时持续改变仿真的质量、摩擦、延迟等参数，使策略面对一组动力学条件而非单一设定。真机参数落在这组条件覆盖的范围内时，策略才有机会保持鲁棒。常见的随机化包括：

- **物理参数**：质量、质心、摩擦、电机增益等。
- **观测噪声**：给传感器读数加噪声、偏置。
- **执行延迟**：模拟真机的控制/通信延迟。

强度要权衡：**随机化太弱**，覆盖不到真机的真实情况，鲁棒性不足；**太强**，任务本身变得过难甚至自相矛盾，策略学不出有效行为。合适的范围应该尽量罩住真机的不确定性，又不至于把任务搅得没法学。这里同样不必穷举所有可随机项，理解"在一族环境上训练"这个思想最重要。

### 6.4特权信息与Asymmetric Actor-Critic / Teacher-Student

critic在训练时可以接收比actor更多的信息。

真机部署时，策略只能用机载传感器能拿到的观测（关节角、IMU等），很多量是测不到的——真实的躯干速度、地面摩擦、外部推力。但在**仿真**里这些量都是已知的，称为**特权信息（privileged information）**。

非对称Actor-Critic（asymmetric actor-critic）利用这一点：

- **actor只看可部署观测**，保证它学到的策略真机上能用。
- **critic额外看特权信息**。回忆critic的作用是估计value/优势，它看得越准，给actor的学习信号就越干净。

注意critic只在训练时用，部署时丢掉。所以特权信息帮助了训练（更准的价值估计、更稳的actor），却不影响策略的可部署性。这是个几乎"免费"的提升。

Teacher-Student（教师-学生）则更彻底地用特权信息：

1. 先训一个 **teacher**：它的actor也能看特权信息，因为信息全、所以容易训出高质量策略。
2. 再训一个 **student**：它只能看真实可部署观测，通过**模仿teacher的动作**来学习（监督式地对齐输出）。
3. student看不到特权量怎么办？用 **latent adaptation**：让student从一段**观测历史**里推断出隐藏状态（比如从最近的关节运动反推地面摩擦、外力），把"看不见的"间接估计出来。

最终student既继承了teacher的高水平行为，又只依赖真机能拿到的观测，可以直接部署。

### 6.5模仿学习（imitation learning）

为什么人形还需要模仿？因为人形的动作空间巨大、搜索极难，纯靠reward从零探索往往学不出自然的动作——能走，但姿态僵硬、步态怪异。给策略一些参考运动（动捕数据、已有轨迹）当引导，能极大缩小搜索范围。几种做法：

- **行为克隆（behavior cloning, BC）**：把"观测→动作"当成监督学习，直接拟合参考数据。简单，但有分布偏移（distribution shift）问题：策略一旦偏离参考轨迹一点点，就进入训练时没见过的状态，误差累积、越偏越远，且自己没学过怎么纠回来。
- **DeepMimic风格的imitation reward**：不抛弃RL，而是在reward里**加入对参考运动的跟踪奖励**（姿态、速度对得上就给分），同时保留任务奖励。这样策略既学得像参考动作那样自然，又因为还在RL框架里、能探索，所以保留了从扰动中恢复的能力——这是相比纯BC的关键优势。
- **AMP / 对抗式模仿**：用一个判别器（discriminator）去学"当前动作像不像参考运动"，把这个"像不像"的打分当作reward。好处是不用手工设计和调一堆跟踪奖励的权重，让判别器自动学出风格度量。一句话理解即可。

### 本部分小结

- Reward设计的核心不是堆term，而是把握原则：策略会优化奖励函数给出的标量，也会出现reward hacking；scale要可比、正负风格要平衡、termination尺度要拿捏。
- 课程学习把任务由易到难带入可学习区间（改变初始状态/命令/环境/reward分布），自动课程按成功率调难度。
- 域随机化让策略在一族动力学上训练以跨越sim2real gap，强度太弱不鲁棒、太强学不动。
- 非对称Actor-Critic让critic看特权信息、actor只看可部署观测；teacher-student先训特权teacher再蒸馏出可部署student，latent adaptation从历史推断隐藏状态。模仿学习（BC / DeepMimic imitation reward / AMP）则用参考运动缩小搜索、学出自然且可恢复的动作。

### 7.1算法全景对比

PPO不是唯一的强化学习算法，它只是大规模并行运控里的主流选择。把常见算法放在一起看，更容易理解它为什么主流。

| 算法 | on/off-policy | 动作空间 | 核心思想 | 在大规模并行humanoid locomotion中的地位 |
| --- | --- | --- | --- | --- |
| DQN | off-policy | 离散 | 学Q值，贪心选动作，经验回放 | 基本不用，连续动作不适用 |
| DDPG | off-policy | 连续 | 确定性策略 + Q网络，actor-critic | 较少用，高维接触任务下不稳 |
| TD3 | off-policy | 连续 | DDPG改进：双Q、延迟更新、目标平滑 | 偶有使用，比DDPG稳但仍难调 |
| SAC | off-policy | 连续 | 最大熵RL，自动温度，样本效率高 | 有人用，样本效率高但高维接触调参难 |
| TRPO | on-policy | 连续/离散 | 用信任区间约束每步更新（硬KL约束） | 思想重要，但实现复杂、算力重，已被PPO取代 |
| PPO | on-policy | 连续/离散 | 用clip近似信任区间，一阶优化 | **主流**，并行仿真下稳定、好实现 |

为什么是PPO？三点：**契合大规模并行仿真**——数千个环境同时跑，on-policy不愁采样量，PPO正好吃得下这种海量新鲜数据；**稳定**——clip/KL把每步更新限制住，不容易训崩；**实现简单**——一阶优化，没有TRPO的二阶/共轭梯度那套复杂机器。

SAC、TD3这类off-policy算法理论上**样本效率更高**（能反复利用回放缓冲里的旧数据），在采样昂贵的场景很香。但在高维、富接触的人形任务里，它们对超参数更敏感、更难稳定，而仿真里采样又足够便宜，于是PPO的"稳 + 简单"压过了off-policy的样本效率优势。

### 7.2 model-free vs model-based / 与MPC的关系

PPO是model-free（无模型的：它不试图学环境的动力学，只通过试错直接学策略。好处是不用建模、对复杂动力学不挑；代价是样本需求大。

model-based（基于模型）则学一个动力学模型（给定状态和动作，预测下一状态），再用这个模型来规划或生成想象的经验。样本效率通常更高，但模型误差会传导到策略上。

和 **MPC（模型预测控制）**对比很能说明问题：MPC也用动力学模型，但它是**在线优化**——每个控制周期都现场解一个有限时域的优化问题选动作，依赖一个准确的模型且计算实时性要求高。RL（如PPO）则是**离线训练、在线推理**——训练时花大量算力学出一个策略网络，部署时只做一次前向推理，极快，但训练成本前置了。

两者也可以**混合**：比如用MPC当teacher生成高质量示范、再用RL学一个能部署的策略；或者让RL只学一个MPC/基础控制器之上的residual（残差）修正，结合模型先验与学习的灵活性。

### 7.5建议学习顺序

按这个顺序学，每一步都为下一步打底，不会卡在悬空的概念上：

1. **MDP基础**：state / observation / action / reward、return、折扣 。先把"问题长什么样"搞清楚。
2. **策略表示**：什么是策略 、连续动作的高斯策略、log\_prob怎么算。
3. **价值与优势**：、、advantage、Bellman方程、TD误差。理解"怎么评判一个动作好不好"。
4. **策略梯度与Actor-Critic**：策略梯度公式、baseline降方差、actor/critic分工。
5. **GAE**：偏差-方差权衡， 的作用。
6. **PPO**：ratio、clipped objective、KL监控、熵。这是主线的终点。
7. **连续控制实践**：动作设计、action scale、观测/优势归一化、探索。
8. **泛化**：reward设计原则、课程学习、域随机化。
9. **模仿与teacher-student**：BC、imitation reward、特权信息蒸馏。

一句提醒：**不要一开始就钻数学证明**。最重要的是把每个公式和真实的训练现象联系起来——看到std不降、value loss不动、reward卡住时，知道公式里哪一项在起作用。直觉建立起来后再回头补严格推导，会顺很多。

### 7.6一页总结

把全文串成一条因果链：

强化学习要解决的是"在一个序列决策问题里学出好策略"。一切从三样东西定义问题开始——**observation决定策略能看见什么**，**action决定它能控制什么**，**reward决定我们想优化什么**。策略本身（连续控制下是高斯 ）把观测映射成动作分布，log\_prob把"采到的动作有多符合当前策略"量化出来。

光有动作还不够，得知道**哪些动作算好**。这就是value和advantage的活：critic估计 ，TD误差和GAE把它组合成优势 ，告诉我们每个动作比平均好多少——这是驱动学习的真正信号。策略梯度据此调整参数：让优势为正的动作更可能、为负的更不可能。

但更新太猛会训崩。**PPO的clip、KL和entropy共同决定改得多快、多稳、多敢探索**——clip把每步更新锁在信任区间里，KL监控偏移幅度，entropy防止探索过早熄火。这套机器配上大规模并行仿真，就是运控里能跑通的训练循环。

最后，仿真里训好不等于真机能用。**curriculum决定任务能不能一步步学得动，domain randomization决定策略能不能跨越sim2real gap，imitation / teacher-student决定动作自然不自然、看不见的状态能不能补回来**——它们共同决定一个仿真里学出的策略，能否真正泛化到现实世界。

这套训练链路从观测定义、动作输出和奖励目标开始，再用value/advantage提供评价信号，用PPO约束单次更新幅度；课程学习、随机化和模仿训练则处理从仿真到真机的差异。
