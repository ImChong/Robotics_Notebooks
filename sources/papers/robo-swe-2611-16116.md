## 原文摘录与 Wiki 映射

- **机制：** 在合并 PR 中筛出可验证 issue 与新增测试，重建修复前容器；用 base→新增测试应失败→加入开发者修复应通过的 F2P/P2P 测试准入门槛筛选，最终向 Agent 隐藏真实修复 patch。
- **实验：** 原文称从 61,655 个 merged PR 筛候选、最终 262 项通过执行准入；项目当前展示 236 个任务及 28 个仓库，需区分论文静态构造与公开榜单口径。
- **局限：** 容器测试通过只说明软件 issue 修复不一定保证真机行为正确；不同模型 harness 与软件栈和任务数量不可直接横比。
- **对 wiki 的映射：** 独立论文详情的核心原理、评测及工程实践。
