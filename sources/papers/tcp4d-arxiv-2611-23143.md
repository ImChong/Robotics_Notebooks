## 核心摘录与知识映射

1. Stage 1：RGB 帧序列、相机与初始 2D TCP 查询进入共享四维几何表示，输出随时间变化的度量 TCP 6D 位姿、开合状态及场景几何。 → [方法说明](../../wiki/entities/paper-tcp4d-2611-23143.md)。
2. Stage 2：读取近期 RGB、机器人状态、语言和上一阶段的轨迹特征，通过条件生成模型预测未来双臂 TCP 与夹爪状态；官方 RoboTwin checkpoint 每窗口输出 32 步，默认每 20 步重规划。 → [方法说明](../../wiki/entities/paper-tcp4d-2611-23143.md)。
3. 跨构型数据增强：跟踪原机器人视频后将 TCP 路径重定向到目标机器人，并经渲染/修复生成配对观测；不能把视频跟踪误差当成新本体真机成功率。 → [方法说明](../../wiki/entities/paper-tcp4d-2611-23143.md)。

## 论文实验事实（非本仓复现）

- 作者在 DROID 跟踪基准报告 TCP 误差 7.60 mm。
- RoboTwin 48 任务 clean-to-clean 轨迹生成平均成功率 69.19%；clean-to-random 为 10.94%，说明扰动泛化仍有缺口。

## 论文局限

- 单目几何与相机标定误差可能污染 TCP 估计，跨本体还受目标机器人可达性与 IK 约束。
- 69.19% 对应特定 RoboTwin 评测设置，不能外推到任意真实机器人。
- 公开 Stage1/Stage2 推理、训练代码及模型；官方声明代码/模型 CC BY 4.0。
