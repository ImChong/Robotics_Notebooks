# The Last AI Built by Humans: Toward Genuine Recursive Self-Improvement

**这篇论文不是一个新模型，而是用五级自治框架和 HCI 衡量 AI 改进闭环离“真正递归自改进”还有多远。**

## 英文缩写速查

| 缩写 | 英文全称 | 简要说明 |
|------|----------|----------|
| RSI | Recursive Self-Improvement | 系统持续改进自身能力及后续改进过程 |
| HCI | Headroom-Closed Index | 将领域能力映射为相对基准前沿的剩余提升空间 |
| AI | Artificial Intelligence | 论文讨论的自动化智能系统总称 |
| SWE | Software Engineering | 文中交互式软件工程等能力测量所涉及的领域 |

## 为什么重要

“AI 能帮忙改进 AI”很容易被用作强结论，但实验自动化、训练时自我迭代、策略/工具自优化和系统自主设计下一轮改进并非同一件事。本文的贡献是提供一把判别尺：既看系统执行改进的能力，也看它能否决定策略、获得新经验、适应变化环境，并进一步改进改进过程本身。对机器人而言，这能帮助审读“自主研发”“自我进化”叙事，避免把自动调参当成闭环 RSI。

## 核心方法与框架

### 五级改进自治

论文将 RSI 能力分解为五个递进方面：

1. **改进执行**：按给定目标或方案运行优化、训练或代码修改。
2. **改进策略**：选择改什么、采用什么搜索/优化路径。
3. **经验获取**：系统主动产生、筛选对后续提升有价值的经验。
4. **环境适应**：面对任务或环境变化调整数据、目标与改进方案。
5. **递归元改进**：改进自身提出、验证和应用后续改进的机制。

这不是仅凭一个 benchmark 分数给系统分级。各层需要不同证据，且前四层的局部成功不能推出第五层已经闭合。

### Headroom-Closed Index（HCI）

HCI 将各能力领域的结果映射到领域基准的相对位置：以某领域基准进入年份的第 90 百分位作为 0 点、满分作为 100，再按样本规模以平方根权重汇总。其目标是表达相对“剩余提升空间”的进展，而不是把不同原始基准分数直接相加。

直觉上，某系统越接近每个领域的既有高分前沿，归一化后的 headroom 指标越高。但跨任务基准的可比性、前沿选取、样本量和证据来源可靠性都会影响结果；HCI 是作者提出的汇总口径，不是已有统一标准或独立验证过的通用能力量表。

### 证据层级与审读路径

论文综合科学、具身智能、软件工程和医疗等方向的公开研究与产业资料，并把能力估计按领域汇总。读者应把框架主张、同行评审实验、预印本、工业报告和厂商自述分层看待。对“系统自主改进”的证据，重点追问：目标是否由人预先指定？数据/经验是否由系统获取？改进策略是否可变？验证器是否独立？跨轮次是否保留并改进了有效方法？

## 工程实践

- **机器人论文/产品审读：** 逐项核对五层，不要因系统能跑自动训练就称作 RSI。
- **设计评测：** 除最终任务成功率外，记录目标由谁设定、经验来源、策略更新、验证独立性、跨轮保留与新环境适应。
- **审计 HCI：** 先核对每个领域的基准、年份、前沿分位点、样本量与数据来源，再看聚合值；不将 HCI 误作成功率或通用智力分数。
- **具身闭环：** 真机还需明确 reset、安全约束、数据采集成本和独立验证；本论文未提供对应控制栈或运行时。

**源码运行时序图：不适用。** 截至 2026-10-09，项目页没有链接可运行的论文实现；关联 GitHub 仓库是 CC0 文献/资源清单，不是训练、推理或部署代码。

## 实验与评测

本文不是提出一个新机器人控制器或统一实验系统，评测部分主要综合已有研究和行业资料，并提出 HCI 作为跨领域的归一化视角。因此，下列数值应视作论文汇编的估计，而非同一协议下的受控对比：作者给出的 2026 HCI 示例包括高等数学 86.4、研究生科学 85.8、广泛知识 77.2、法律推理 64.5、多模态推理 62.2、前沿学术广度 60.4、交互式软件工程 52.6、搜索/终端 agent 56.8、工具 agent 39.9。

这些数值对能力分布的启发大于点估计本身。论文强调基准口径异质、来源可信度不等；尤其产业自报结果要谨慎折扣。HCI 的作用是组织证据和提示 headroom，不应被解读为模型已完成相同比例的递归闭环。

## 结论

**本文最有用的是对“自改进”做层次化判别；HCI 是组织异质证据的提案，不是 RSI 已实现或即将实现的证明。**

1. **区分五层能力**：执行既定改进不等于系统能决定改进策略，更不等于元改进闭环。
2. **把 HCI 当导航而非成绩单**：比较前先检查基准归一、年份前沿、样本量与来源折扣。
3. **把证据来源分层**：行业自报、公开案例、预印本和同行评审实验的证明力不同。
4. **机器人系统补测闭环条件**：目标设定、经验采集、安全 reset、独立 verifier 与跨环境泛化都应单独报告。
5. **不要期待代码复现路径**：当前公开配套 GitHub 是策展索引，未见本文方法的可运行实现。

## 局限与风险

- **框架不是因果验证。** 五层适合作为审读维度，但层间递进关系并不自动证明任何具体系统走完了闭环。
- **HCI 依赖选择。** 领域、基准、进入年份前沿、样本规模权重和来源折扣会改变估计；不同选择可能影响横向结论。
- **证据异质。** 论文纳入公开学术与产业材料，成熟度不一；汇总值不能替代逐项核验。
- **具身证据有限。** 机器人闭环受到真实经验采集、硬件安全和环境变化约束；文中讨论不等于可部署实现。
- **标题是研究议程式表述。** 不应将其读成“最后一个人类建造的 AI 已经出现”的事实断言。
- **源码状态：** 截至 2026-10-09 未见项目页提供的论文专属可运行实现或数据集；官方关联仓库为文献清单。
