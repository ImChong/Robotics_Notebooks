# Introducing BDD — Dan North

- **类型：** 作者原文 / 方法说明
- **链接：** https://dannorth.net/blog/introducing-bdd/
- **作者：** Dan North
- **原文日期：** 2006-09-20
- **核查日期：** 2026-10-13
- **一句话说明：** BDD 发起者对其动机与早期实践的原始解释：把测试过程重新表述为行为、场景和共享领域语言，降低沟通歧义。

## 核心摘录

- North 的出发点是让测试方法更贴近开发者表达系统行为的方式：从“测试某个方法”转向描述某个上下文中系统应该做什么。
- BDD 把用户/业务故事、具体示例、行为规格和自动化反馈连起来，并鼓励团队复用业务领域语言。
- Given / When / Then 是常用场景书写形式，但不是 BDD 的全部；仅把单元测试套上 Gherkin 语法，不等于形成跨角色行为发现与协作。
- 该原文体现 BDD 的历史动机；其后实践已经扩展，当前解释还应结合 Cucumber 官方文档和团队语境。
