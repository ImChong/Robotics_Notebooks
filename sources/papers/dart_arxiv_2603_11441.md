## 摘录 1：问题与核心不变量（Abstract / §1）

- **痛点：** SAM3 每类需独立前向，439M 骨干成本 **O(N)**；N 类开放词汇检测在机载/实时场景不可接受。
- **不变量：** SAM3 视觉骨干 **class-agnostic**，图像特征与文本提示无关 → 骨干可 **跨类别共享一次**，成本从 O(N) 降到 **O(1)**。
- **叠加：** 批量多类解码、检测专用推理路径、TensorRT FP16；3 类累计 **5.6×**，80 类 **25×** 加速（相对逐类 SAM3）。

## 摘录 2：精度与速度（Abstract / README）

| 设置 | 结果 |
|------|------|
| COCO val2017，80 类，1008×1008 | **55.8 AP**，**15.8 FPS**（4 类批、单卡 RTX 4080） |
| 对比 | 超过在数百万框标注上训练的专用开放词汇检测器 |
| 极低延迟选项 | 冻结 encoder-decoder 的 adapter 蒸馏 + student 骨干：**38.7 AP**，骨干 **13.9 ms** |
| 延伸 DARTF | Jetson AGX Orin W8A8 INT8：1008 px 帧 **275 ms → 158 ms**（1.74×），COCO AP 与 FP32 持平 |

**对 wiki 的映射：** 实体页「结论」强调：**真影响指标是骨干共享 + TRT**；蒸馏是极端延迟备选。

## 摘录 3：工程入口（README）

1. 一次性构建共享 **enc-dec** TensorRT engine（`sam3.trt.export_enc_dec` → `build_engine`）。
2. 选择骨干：ViT-H 全量 / Pruned-16 / RepViT 等 student（HF 权重）。
3. 运行检测：`scripts/export_hf_backbone.py` + 视频管线；可选 tracking / COCO eval。

**对 wiki 的映射：** 源码运行时序图对齐 `export_*` → TRT engine → 推理脚本。
